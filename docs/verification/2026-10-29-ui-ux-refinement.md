# UI/UX 정돈 검증 기록

기준일: 2026-10-29. 기준 소스: `df02594`.

## 관찰과 수정

운영 사이트의 데스크톱 첫 화면에서 두 도메인은 같은 진단 화면을 표시했다. `ilina.kr`은 소스상 아래에 추가 자료 영역과 별도의 브랜드 콘텐츠를 갖는다. 시작 화면의 특성 설명과 참고 문구, 서비스 푸터는 작고 연한 회색이어서 읽기 어려웠고, 정보 및 닫기 버튼은 36px이었다. 제품 카드의 분류와 태그도 작았다.

| 영역 | 이전 | 이후 | 이유 |
| --- | --- | --- | --- |
| 공통 시작 화면 | 36px 정보·닫기 버튼, 연한 특성 설명과 작은 참고 문구 | 44px 버튼, 진한 설명과 12px 참고 문구 | 터치와 가독성 개선 |
| 공통 푸터 | 10.88px 연한 텍스트와 작은 링크 | 12px 진한 텍스트, 44px 높이 링크 | 가독성과 터치 개선 |
| 제품 카드 | 약 10px 분류·태그 | 12px 분류·태그, 분류 색상 강화 | 제품 정보 읽기 개선 |
| 결과·추천 동작 | 다시 검사 40px, 결과 복귀 20px, 제품 링크 16px, 추가 추천 40px | 각각 최소 44px | 터치 영역 확보 |
| 전체 | 일부 화면에 개별 초점 표시 | 링크·버튼·접기 요소에 공통 초점 표시 | 키보드 이동 가시성 |

색상 계열, 카드 모양, 레이아웃, 문구, 설문·결과·추천 데이터와 로직은 유지했다. 라우팅, SEO 및 메타데이터 파일도 변경하지 않았다. 루트의 피부타입 서비스 연결성은 현재 첫 화면에서 드러나지만, 브랜드명과 서비스의 관계를 더 명확히 설명할 여지는 있다. 문구나 구조 수정은 이번 범위에서 제외했다.

## 검증

- `npm run lint`, `npm run build`: 통과.
- `scripts/verify-service-hosts.py`: 두 호스트의 라우팅, canonical/OG, sitemap 등 검사 통과.
- 로컬 production 브라우저(데스크톱): 시작 → 33문항 → DRNT 결과 → 제품 추천 → 결과로 돌아가기 통과. 해당 흐름의 브라우저 콘솔 오류 없음.
- 운영 두 도메인: UI 커밋 `879548d`의 Vercel 배포 완료 후 실제 HTTPS 시작 화면과 DRNT 공개 제품 화면을 확인했다. 390px 시작·제품 화면에서 가로 넘침이 없었고 정보 버튼, 푸터 링크 및 확인한 제품 조작 영역은 44px이었다. skin 제품 화면은 1440px에서도 시각 확인했으며 확인한 페이지에 콘솔 오류는 없었다. 운영에서 33문항 전체를 재입력한 검사는 수행하지 않았다.
- 후속 검증: 로컬 production 서버에 각 호스트 헤더를 전달하는 프록시를 통해 두 호스트의 설문 33문항 → DRNT 결과 → 추천 → 결과 복귀를 각각 확인했다. 실제 운영 도메인의 저장소·TLS 환경을 재현한 검사는 아니다.
- 브라우저 뷰포트 375, 390, 768, 1440px에서 두 호스트의 시작·설문·가이드 및 유형별 제품 화면, skin의 결과·세션 추천, 루트의 회사 화면을 검사해 문서 가로 넘침이 없었다. 375px 시작과 390px·1440px 추천 화면을 시각 확인했다. 모든 유형과 모든 화면의 시각 회귀를 확인한 것은 아니다.
- 시작 버튼 72px, 정보 버튼 및 공통 푸터 링크 44px, 결과의 다시 검사 링크, 추천 화면의 결과 복귀·제품 링크·추가 추천 버튼은 최종 빌드의 두 호스트에서 각각 44px로 측정했다. 키보드로 시작 버튼에 이동했을 때 2px 초점 테두리를 확인했다. 두 설문 흐름에서 수집된 콘솔 오류는 없었다.

## 후속 확인

모든 16유형과 모든 개별 페이지의 시각 회귀 및 실제 모바일 기기 검사는 별도 검토한다. 기존 브랜드 소개와 첫 화면 사이의 관계를 더 명확히 할지 콘텐츠·구조 변경으로 별도 검토한다.
