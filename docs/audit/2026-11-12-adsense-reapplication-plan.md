## 현재 확인한 운영 상태

11/12 공개 HTTP 확인에서 `/`, `/about`, `/guides/four-dimensions`, `/skin-type/dspw/products`, `/robots.txt`, `/ads.txt`, `/sitemap.xml`은 모두 200이었다. 대표 네 HTML의 canonical은 루트 주소를 가리켰다. robots는 공개 페이지 접근을 허용하고 내부·개발 경로만 제외했다. ads.txt에는 기존 게시자 ID가 있다.

**수정 전 운영 제품 페이지에는 큐레이터 고지가 없었다.** 로컬에서 준비한 변경과 운영 반영은 별개다. 상세 응답 기록: `docs/verification/2026-11-12-live-before.json`. 이번 공개 확인은 Googlebot의 실제 렌더링·계정 심사·전체 사이트 크롤링 검증이 아니다.

## 공식 기준과 외부 사례

1. [Google AdSense 사이트 준비 안내](https://support.google.com/adsense/answer/7299563?hl=en): 사용자에게 필요한 고유 콘텐츠와 탐색 경험을 확인하도록 한다. 이 안내에는 승인에 필요한 고정 글 수·글자 수·방문자 수를 제시하지 않는다.
2. [Google 게시자 정책: Inventory value](https://support.google.com/adsense/answer/10502938?hl=en): 콘텐츠가 없거나 가치가 낮은 화면, 탐색·알림용 화면과 부가가치 없는 복제 콘텐츠 등에 광고를 제한한다. ‘도구 사이트는 무조건 불가’라는 조항으로 읽으면 안 된다.
3. [Search Central의 외부 링크 표시](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links): 광고·유료 관계 링크는 `rel="sponsored"`로 표시한다. 이는 검색엔진에 관계를 알리는 방법이며 사용자 대상 수수료 고지를 대신하거나 AdSense 승인을 보장하지 않는다.
4. [도구 운영자 appadrevenue.com의 8회 거절 후 승인 자가 보고](https://www.reddit.com/r/Adsense/comments/1x0rb4a/finally_after_8_rejections_from_adsense_i_was/): 운영자는 글과 페이지를 추가한 뒤 승인됐다고 설명했고 댓글에서는 약 10개 글, 일 방문자 약 40명을 언급했다. 정확한 승인 원인을 Google이 확인한 사례는 아니다. 이 숫자를 목표치나 임계값으로 채택하지 않는다.
5. [NotchTools 운영자의 반복 거절 질문](https://www.reddit.com/r/Adsense/comments/1jjczj9/how_to_get_adsense_approval_for_my_tool_website/): 도구별 설명을 붙여도 거절됐다는 출발점이다. 후속 댓글은 광고 노출을 언급하지만 작성자의 통제된 전후 비교와 승인 사유는 없다. ‘글만 추가하면 해결’의 증거로 사용할 수 없다.

사례에서 얻는 실행 가설은 **기능 주변에 실제 이용자를 돕는 설명을 연결하고 그 설명의 발견성과 품질을 점검하자**는 정도다. 커뮤니티의 ‘몇만 PV’, ‘글 몇 개’, ‘AI면 무조건 거절’, ‘승인용 블로그로 잠시 바꾸기’ 주장은 공식 기준으로 채택하지 않았다. Search Central의 검색 품질 기준과 AdSense 승인 기준도 동일시하지 않는다.

## 재신청 전에 완료할 운영 확인

아래는 Google의 공식 승인 체크리스트가 아니라 이 프로젝트의 내부 출고 기준이다. **푸시 성공만으로 재신청 준비 완료로 처리하지 않는다.**

- [ ] 가장 최근 거절 날짜·정확한 문구·신청 사이트 URL 기록. 별도 계정 또는 접근 문제가 없는지 확인.
- [ ] 이번 커밋의 배포 성공 및 운영 `/about#scoring`, 4축 가이드, 대표 유형 2개, 제품 2개에서 실제 새 내용 확인.
- [ ] Search Console에서 홈/소개/가이드/유형/제품의 대표 URL을 검사해 Google 선택 canonical, 마지막 크롤링, 렌더링·리소스 접근 확인. site: 검색을 전체 색인 증거로 대체하지 않음.
- [ ] 휴대폰에서 홈 → 33문항 → 결과 → 제품 → 결과 복귀를 확인. 펼침 정보가 읽히며 수수료 고지가 제품 링크보다 먼저 보이는지 확인.
- [ ] 큐레이터 링크 15개의 실제 리디렉션 상품·용량과 독립 웹사이트 사용 범위 확인. 결제나 구매까지 수행할 필요는 없음.
- [ ] 구달·일리윤 보류 사유 해소 또는 보류 상태 유지 확인. 보류 상태에서 구매를 권하지 않음.
- [ ] 문항 출처·권리, 실제 검토 주체·검증 기록 확인. 확보한 사실만 공개하고 허구의 전문 검수자를 넣지 않음.
- [ ] 콘텐츠를 읽은 이용자가 ‘내 결과의 의미’, ‘왜 이 후보인지’, ‘어떤 한계인지’를 설명할 수 있는지 실제 피드백 수집. 수치상 체류시간 목표는 승인 조건으로 쓰지 않음.

날짜만 기다렸다가 반복 제출하지 않는다. 위 증거가 갖춰지고 AdSense 화면에서 재검토 요청이 가능할 때 신청한다. 크롤링이나 색인 완료도 승인의 충분조건은 아니다. 다음 거절에도 같은 문구라면 제출일·배포 SHA·변경 URL·심사 결과를 한 행씩 누적하여 실제로 무엇이 달라졌는지 비교한다.

## 다음 콘텐츠 작업

1. 현재 33문항의 원문·설계 근거를 운영자가 확보하고 공개 가능한 출처와 설명을 연결한다. 현 코드의 임계값 공개는 타당성 입증과 별개다.
2. 유형별 문구 전체를 전문적으로 검토한다. 근거 없는 생리적 단정은 줄이고, 인접 유형 간 차이를 설명할 수 없으면 공통 안내로 통합한다.
3. 제품 성분/처방 변경, 판본과 용량을 기록하는 편집 이력을 유지한다. 현재 고정 매핑과 순서는 개인별 알레르기·병력·실제 반응을 반영하지 않는다. 특히 민감 유형의 기능성 세럼 우선 노출은 추가 검토 대상이다.
4. 새 글은 실제로 반복되는 사용자 질문이 있을 때 쓴다. 승인용 분량 채우기, 체험하지 않은 후기, 근거 없는 효과 비교를 만들지 않는다.
